# คู่มือ 3 — ติดตั้ง H3

ถึงตรงนี้คุณควรจะมี: เครื่องที่เช่ามาแล้ว, จอดำ (Terminal) เปิดอยู่, และ `HF_TOKEN` ใส่ไว้แล้ว
ถ้ายังไม่ครบ ย้อนไป [คู่มือ 1](01-rent-vast.md) กับ [คู่มือ 2](02-hf-token.md) ก่อน

## ขั้นที่ 1 — ดึงชุดติดตั้งลงเครื่อง

วางคำสั่งนี้ในจอดำแล้วกด `Enter`

```bash
cd /workspace && git clone https://github.com/capruokz/h3-comfy && cd h3-comfy/skills/h3-setup/scripts
```

**จะเห็นอะไรตอนสำเร็จ** — มีข้อความ `Cloning into 'h3-comfy'...` แล้วจบด้วยบรรทัดที่มีคำว่า
`done` และตัวอักษรกะพริบกลับมา ใช้เวลาไม่กี่วินาที

## ขั้นที่ 2 — ตรวจเครื่องก่อน

ก่อนโหลดไฟล์ 38 GB เราจะเช็คก่อนว่าเครื่องนี้ตั้งค่ามาถูกหรือเปล่า

```bash
python3 check_stack.py
```

**ทำไมต้องเช็คก่อน** — ถ้าเครื่องตั้งค่ามาผิด มันจะยัง**เจนคลิปออกมาได้ปกติ ไม่มี error อะไรเลย
แค่ช้ากว่าที่ควรหลายเท่า** เคยเจอมาแล้วว่าช้ากว่าที่ควร 5.2 เท่า และกว่าจะรู้ตัวก็จ่ายค่าเช่า
ไปแล้วครึ่งวัน — การมารู้หลังโหลดเสร็จคือวิธีเรียนรู้ที่แพงที่สุด

**อ่านผลยังไง**

| ขึ้นว่า | แปลว่า | ทำยังไงต่อ |
|---|---|---|
| `[ผ่าน]` ทุกบรรทัด | เครื่องพร้อม | ไปขั้นที่ 3 |
| มี `[ควรรู้]` | ไม่ถึงกับพัง แค่บอกให้รู้ | **ไปต่อได้เลย** |
| มี `[ต้องแก้]` | เครื่องนี้จะช้าผิดปกติ | ทำขั้นที่ 2.5 ข้างล่าง |

**ถ้าเผลอเช่าการ์ดรุ่นเก่ามา** สคริปต์จะบอกตั้งแต่ตรงนี้ ก่อนโหลดไฟล์ 38 GB
แล้วบอกวิธีเปลี่ยนเครื่องให้ทีละขั้น เสียแค่ค่าเช่าไม่กี่นาที ไม่ใช่ค่าเน็ตก้อนใหญ่

```
การ์ดใบนี้เก่ากว่าที่ชุดนี้รองรับ

  ชุดนี้รองรับเฉพาะ NVIDIA ตระกูล Blackwell ขึ้นไป ได้แก่
    RTX 5060 Ti · 5070 · 5070 Ti · 5080 · 5090 · RTX PRO 6000 Blackwell · B200

  ทำยังไงต่อ:
    1. กลับไปหน้า Instances บน vast.ai แล้วกด Destroy เครื่องนี้
    2. ที่หน้า Search พิมพ์ค้นว่า  5090  หรือ  5080  หรือ  5060
    3. เช่าใหม่แล้วเริ่มจากคู่มือ 3 ขั้นที่ 1 อีกครั้ง
```

## ขั้นที่ 2.5 — ถ้าเจอ FAIL

ลองให้สคริปต์แก้ให้ก่อน

```bash
bash setup.sh --fix
```

คำสั่งนี้จะลงเวอร์ชันที่ถูกต้องให้แล้วติดตั้งต่อเลย **ใช้เวลาราว 5–15 นาที**
ระหว่างนี้จะมีข้อความไหลผ่านเยอะมาก ไม่ต้องอ่าน

**ถ้ายังไม่ผ่านอีก** แปลว่าเครื่องที่เช่ามาใช้อิมเมจที่เก่าเกินไป —
กลับไปหน้า Instances กด **Destroy** แล้วเลือกเครื่องใหม่ ยังดีที่ยังไม่ได้จ่ายค่าโหลด 38 GB

## ขั้นที่ 3 — ติดตั้ง

```bash
bash setup.sh
```

**ใช้เวลาประมาณ 10–25 นาที** ขึ้นกับความเร็วเน็ตของเครื่องที่เช่า
ระหว่างนี้จะมีแถบความคืบหน้าวิ่งไปเรื่อยๆ ปล่อยมันไป **อย่าปิดแท็บ**

มันกำลังทำ 5 อย่าง:

1. โหลดไฟล์โมเดล 6 ไฟล์ รวม 38 GB
2. ดึง custom node 6 ชุด (ล็อกเวอร์ชันไว้แล้ว)
3. แก้ไฟล์ของ node ตัวหนึ่งที่มีบั๊ก (ดูหัวข้อสุดท้าย)
4. เปิด ComfyUI ใหม่พร้อมค่าที่เร็วที่สุด
5. เช็คว่ากลับมาทำงานได้จริง

**จะเห็นอะไรตอนสำเร็จ** — บรรทัดสุดท้ายจะขึ้นคำว่า

```
ready
```

ถ้าเห็นคำนี้แปลว่าติดตั้งเสร็จแล้ว

## ขั้นที่ 4 — เริ่มใช้งานได้เลย

ติดตั้งเสร็จแล้ว เจนคลิปได้เลย ไม่ต้องตั้งค่าอะไรเพิ่ม

**ความยาวคลิปที่แนะนำสำหรับครั้งแรก: 8 หรือ 10 วินาที** ปลอดภัยกับการ์ดทุกใบที่ชุดนี้รองรับ

---

## เรื่องเดียวที่ควรรู้ไว้: คลิปยาวเกินไปจะช้าลงมาก

**อาการนี้ไม่มี error** คลิปยังออกมาครบทุกอย่าง แค่ใช้เวลานานกว่าที่ควรสองสามเท่า
เกิดจากการ์ดเก็บข้อมูลไว้ในตัวเองไม่พอ เลยต้องรูดไปกลับกับแรมของเครื่อง

**วิธีสังเกต** ลองเทียบเวลาที่ใช้ต่อคลิป ถ้าเพิ่มความยาวคลิปขึ้นนิดเดียว
แต่เวลาที่ใช้พุ่งขึ้นเท่าตัว แปลว่าเลยจุดนั้นมาแล้ว **ถอยกลับมาความยาวก่อนหน้า**

**ยืนยันได้จากกำลังไฟ** เปิดจอดำอีกหน้าต่างแล้วพิมพ์:

```bash
nvidia-smi --query-gpu=utilization.gpu,power.draw,power.limit --format=csv
```

ถ้าใช้งาน 100% แต่กินไฟไม่ถึงครึ่งของค่าสูงสุด (เช่น `48 W` จาก `180 W`)
นั่นคือกำลังรูดแรมอยู่ ไม่ใช่กำลังทำงาน

**ตัวเลขอ้างอิง** บนการ์ด 16 GB ที่ใช้เขียนคู่มือนี้ จุดหักอยู่ระหว่าง 294 กับ 362 เฟรม
(ราว 12 กับ 15 วินาที) การ์ดที่ VRAM มากกว่าจะไปได้ไกลกว่านี้มาก

> อยากรู้เพดานของการ์ดตัวเองแบบเป๊ะๆ มีสคริปต์วัดให้อยู่ที่
> `skills/h3-setup/scripts/find_ceiling.py` — **ไม่จำเป็นต้องรัน** มันไล่เจนคลิปทีละความยาว
> ใช้เวลา 10–20 นาที ซึ่งเป็นเวลาที่จ่ายค่าเช่าอยู่ ทำก็ต่อเมื่ออยากรีดคลิปให้ยาวที่สุด
> เท่าที่การ์ดไหว

## แก้ปัญหาที่เจอบ่อย

**ขึ้น `401` หรือ `403` ตอนโหลดโมเดล**
→ ยังไม่ได้กดยอมรับเงื่อนไขของโมเดล กลับไปทำ [คู่มือ 2 ขั้นที่ 3](02-hf-token.md)
หรือ token หมดอายุ/พิมพ์ตกไปตัวหนึ่ง ลองพิมพ์ `echo ${HF_TOKEN:0:6}...` ดู

**ขึ้น `no HF_TOKEN set`**
→ ปิดจอดำแล้วเปิดใหม่ ทำให้ค่าที่ตั้งไว้หายไป พิมพ์ `export HF_TOKEN=hf_xxxx` ใหม่

**ขึ้น `หา ComfyUI ไม่เจอ`**
→ เครื่องที่เช่าไม่ได้ใช้เทมเพลตที่มี ComfyUI ถ้ารู้ว่ามันอยู่ตรงไหน สั่งแบบนี้ได้:
```bash
COMFY=/path/to/ComfyUI bash setup.sh
```

**โหลดเร็วอยู่ดีๆ แล้วร่วงเหลือหลักร้อย kB/s · แถบ `reconstructing file` ค้างนิ่งไม่ขยับ**
→ เครื่องนั้นต่อไปยัง CAS backend ของ Xet ได้ไม่ดี ปิด Xet แล้วรันใหม่:
```bash
export HF_HUB_DISABLE_XET=1
bash setup.sh
```
ไฟล์ที่โหลดจบแล้วจะไม่โหลดซ้ำ

**อย่าเพิ่งปิด Xet ถ้ายังไม่เจออาการนี้** — วัดบนเน็ตปกติแล้ว Xet เร็วกว่า
(605 MB: 59.7 เทียบ 52.8 MB/s · 780 MB: 72.8 เทียบ 30.7 MB/s) ปิดไว้ตลอดคือช้าลงเปล่าๆ

สังเกตให้ถูกจุด: Xet มีสองแถบ `downloading bytes` คือเน็ตจริง ส่วน `reconstructing file`
คือการประกอบไฟล์ในดิสก์ แถบบนเต็มก่อนแล้วแถบล่างค่อยเริ่มจาก 0% เป็นเรื่องปกติ
ที่ผิดปกติคือ**แถบล่างค้างตัวเลขเดิมนานเกินสองสามนาที**

**กด Enter แล้วเด้งกลับมาที่บรรทัดคำสั่งเฉยๆ ไม่มีข้อความอะไรเลย**
→ เป็นบั๊กที่แก้แล้ว ถ้ายังเจอแปลว่าชุดที่ดึงมาเก่า `cd h3-comfy && git pull` แล้วลองใหม่

สาเหตุเดิมคือ `comfy_env.sh` หาโปรเซส ComfyUI ที่รันอยู่ด้วย `pgrep` แล้วถ้าไม่เจอ
มันคืนค่าล้มเหลว ซึ่ง `set -e` ของ `setup.sh` เอาไปฆ่าตัวเองทิ้งก่อนพิมพ์อะไรออกมา
จึงขึ้นกับจังหวะล้วนๆ ว่าตอนกดคำสั่งนั้น ComfyUI กำลังรันอยู่หรือเปล่า —
กดตอนมันกำลังบูตหรือกำลังรีสตาร์ทก็เงียบ กดตอนมันรันอยู่ก็ผ่าน

ระหว่างที่ยังไม่ได้ `git pull` ข้ามการตรวจโปรเซสไปเลยก็ได้:
```bash
COMFY=/workspace/ComfyUI bash setup.sh --fix
```

**การติดตั้งช้ามาก (เกินครึ่งชั่วโมง)**
→ เครื่องนี้เน็ตช้า ยกเลิกด้วย `Ctrl+C` แล้ว Destroy ไปเลือกเครื่องที่ Mbps สูงกว่า
จ่ายค่าเช่ารอโหลดแพงกว่าค่าเช่าเครื่องที่ดีกว่า

**ขึ้น `No matching distribution found for sageattention>=2.2`**
→ `setup.sh` รุ่นเก่าลงจาก PyPI ซึ่งมีถึงแค่ 1.0.6 รุ่นใหม่คอมไพล์จากซอร์สให้แล้ว
`git pull` แล้วรัน `bash setup.sh --fix` ซ้ำ ถ้าอยากลงเองมือ:
```bash
MAX_JOBS=32 python3 -m pip install -v --no-build-isolation \
    git+https://github.com/thu-ml/SageAttention.git
```

**ComfyUI ตายกลางคันโดยไม่มี error ในล็อกเลย**
→ เจอบ่อยกับการ์ด 16 GB: โมเดล 17.7 GB ถูก stage ไว้ในแรมระบบ ถ้าหน่วยความจำก้อนนั้น
ถูกล็อกห้ามสลับออก เคอร์เนลจะฆ่าโปรเซสทิ้งกลาง sampling step แรก **ไม่มี traceback
ไม่มี `torch.OutOfMemoryError`** เพราะถูกฆ่าจากนอกโปรเซส
รัน `restart_comfy.sh` ตัวใหม่ (ใส่ `--disable-pinned-memory --fast-disk` ให้แล้ว)
ถ้าเปิดเองให้ใส่สองแฟล็กนี้ด้วยเสมอ

**หา log ไม่เจอ / log ไม่มีอะไรเปลี่ยน**
→ ถ้า `restart_comfy.sh` เปิดแบบถือโปรเซสเอง log จะอยู่ที่ **`/workspace/comfy.log`**
ไม่ใช่ `/workspace/ComfyUI/comfy.log` ซึ่งเป็นของโปรเซสเก่าที่ supervisor เคยถือ

**หน้า Supervisor ขึ้น `comfyui STOPPED` ทั้งที่ ComfyUI ใช้งานได้**
→ ปกติสำหรับกรณีที่ต้องถือโปรเซสเอง supervisor มองไม่เห็น อย่ากดปุ่ม Start ทับ
เพราะจะแย่งพอร์ตกับตัวที่รันอยู่ ตรวจว่าเปิดจริงไหมด้วย `/system_stats` แทน

**ขึ้น `cusparse.h: No such file or directory`**
→ อิมเมจนี้มีตัวคอมไพล์แต่ไฟล์ประกอบไม่ครบ `setup.sh --fix` จัดการให้อยู่แล้ว
ถ้ายังไม่หายแปลว่าอิมเมจเก่าเกินไป เปลี่ยนเครื่อง

## เรื่องที่คนเอาไปใช้ต่อควรรู้

ขั้นที่ 3 ข้อ 3 **เขียนทับไฟล์ของโปรเจกต์คนอื่น** (`ComfyUI-MiniMax-H3-Turbo/__init__.py`)
เพราะโหนดตัวนั้นจะพังทันทีที่ต่อไฟล์เสียงอ้างอิงเข้าไป ซึ่งคลิปที่มีบทพูดต้องใช้ทุกคลิป

ของเดิมถูกเก็บไว้ที่ `__init__.py.stock` ถ้าอยากคืนค่า ก๊อปกลับได้
แพตช์นี้ผูกกับเวอร์ชันที่ล็อกไว้ ถ้าคุณอัปเดต node เป็นเวอร์ชันใหม่กว่า
ให้ลองถอดแพตช์ก่อนแล้วดูว่าต้นทางแก้ให้แล้วหรือยัง
